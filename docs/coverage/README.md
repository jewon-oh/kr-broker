# 지원 범위 자료

폴더에는 증권사 공식 API와 라이브러리의 지원 범위를 기록한 자료가 있습니다.

문서 생성기(`scripts/gen-broker-docs.mjs`)가 자료를 읽어 `docs/brokers/`의 문서를 만듭니다. README의 지원 표와 요약도 같은 자료에서 채웁니다.

생성된 문서는 손으로 고치지 않습니다. 자료를 고치고 문서를 다시 만듭니다.

## 파일

| 파일 | 내용 |
|---|---|
| `kis.json` | 한국투자증권의 공식 API 목록과 지원 상태 |
| `toss.json` | 토스증권의 공식 API 목록과 지원 상태 |
| `kbsec.json` | KB증권의 공식 API 목록과 지원 상태 |
| `features.json` | 기능과 증권사를 교차한 지원 매트릭스 |

## 고치는 순서

1. 코드를 고쳐 API를 더하거나 바꿉니다.
2. `docs/coverage/`의 자료를 코드와 맞게 고칩니다.
3. `pnpm docs:gen`을 실행해 `docs/brokers/`를 다시 만듭니다.
4. 자료와 생성된 문서를 함께 커밋합니다.

`ts/src/__tests__/docs-coverage.test.ts`가 자료와 코드가 어긋나면 실패합니다. 검사 내용은 다음과 같습니다.

- 자료가 스키마에 맞고 `id`가 겹치지 않습니다.
- `describe().api`의 모든 엔드포인트가 자료에 있고 상태가 `missing`이 아닙니다.
- 상태가 `integrated`나 `extended`인 항목의 `method`가 클래스에 있습니다.
- `has`가 `true`나 `emulated`인 메서드 키가 `features.json`에 있습니다.
- 기능 표의 셀 값이 `has`와 맞고, 구현으로 적은 셀의 메서드가 클래스에 있습니다.
- `evidence`가 빈 줄이나 다른 API의 정의 줄이 아니라 그 API를 가리킵니다.
- 생성기가 만든 결과가 커밋된 `docs/brokers/`와 같습니다.

`pnpm docs:check`는 마지막 두 항목을 검사합니다. CI가 `docs:check`를 실행합니다.

## 증권사 파일

### 최상위 키

| 키 | 뜻 |
|---|---|
| `schemaVersion` | 스키마 버전입니다. 지금은 `1`입니다. |
| `broker` | 증권사 클래스 이름입니다. 파일 이름과 같습니다. |
| `name` | 증권사 이름입니다. |
| `checkedOn` | 공식 API 목록과 코드를 대조한 날짜입니다(`YYYY-MM-DD`). |
| `profile` | 클래스 요약입니다. 인증 필드, 모의투자, 지원 시장, 호출 한도를 담습니다. |
| `sources` | 공식 API 목록의 출처입니다. `name`과 `url`을 가집니다. |
| `priorities` | 미구현 API의 우선순위 번호와 설명입니다. 없어도 됩니다. |
| `apis` | 공식 API 항목의 배열입니다. |
| `uniqueFeatures` | 증권사에서만 쓰는 기능의 배열입니다. |
| `limitations` | 알려진 한계의 문장 배열입니다. |

### `profile`

- `class`는 클래스의 `id`입니다.
- `credentials`는 `apiKey`, `secret`, `uid`마다 `label`, `required`, 선택 `note`를 가집니다. `required`는 클래스의 `requiredCredentials`와 같아야 합니다.
- `sandbox`는 `supported`와 `note`를 가집니다. `supported`는 `has.sandbox`와 같아야 합니다.
- `markets`는 `KR`과 `US` 중에서 고릅니다.
- `rateLimit`은 `ms`와 `note`를 가집니다. `ms`는 클래스의 `rateLimit`과 같아야 합니다.

### `apis` 항목

증권사가 공개한 API 하나가 항목 하나입니다. 웹소켓 채널도 항목 하나로 집계합니다.

| 키 | 뜻 |
|---|---|
| `id` | 증권사 파일 안에서 유일한 식별자입니다. 토스증권은 `메서드 경로`, KB증권은 TR 코드, 한국투자증권은 공식 예제 경로입니다. |
| `category` | 증권사가 붙인 분류입니다. 한국투자증권은 `분류 > 소분류` 형식입니다. |
| `name` | API 이름입니다. |
| `endpoint` | `GET /api/v1/prices` 형식입니다. 웹소켓은 `WS`와 채널 이름이나 TR ID입니다. |
| `markets` | 증권사가 밝힌 지원 시장입니다. `KR`과 `US` 중에서 고릅니다. |
| `status` | 지원 상태입니다. 아래 표를 봅니다. |
| `method` | 응답을 반환하는 공개 메서드입니다. 없으면 `null`입니다. |
| `evidence` | 구현 위치를 `경로:줄` 형식으로 적은 배열입니다. |
| `suggested` | 미구현 API를 연결할 때 쓸 메서드 이름 후보입니다. 없으면 `null`입니다. |
| `proposal` | 제안 유형입니다. `통합`, `확장`, `params 확대`, `watch*` 중 하나이거나 `null`입니다. |
| `priority` | 미구현 API의 우선순위입니다. 작은 수가 먼저입니다. `missing` 항목에만 씁니다. |
| `verified` | 검증 수준입니다. 아래 표를 봅니다. |
| `note` | 제한이나 특이 사항을 적은 설명입니다. 없으면 빈 문자열입니다. |
| `spec` | 공식 명세의 위치를 가리키는 URL입니다. |

`status` 값은 다음과 같습니다.

| 값 | 뜻 |
|---|---|
| `integrated` | ccxt 통합 메서드가 응답의 주된 출처입니다. |
| `extended` | 전용 공개 메서드가 응답을 반환합니다. |
| `implicit` | `api` 트리에만 있고 암묵 메서드로 직접 호출합니다. 공개 메서드는 없습니다. |
| `internal` | 다른 메서드가 내부에서만 호출합니다. |
| `missing` | 연결하지 않았습니다. |

`verified` 값은 다음과 같습니다.

| 값 | 뜻 |
|---|---|
| `real` | 실계좌 응답으로 확인했습니다. |
| `sandbox` | 모의투자 서버 응답으로 확인했습니다. |
| `spec-only` | 공식 명세나 예제만 보고 구현했고 호출 기록을 확인하지 못했습니다. 미구현 API에도 `spec-only`를 적습니다. |
| `unverified` | 구현했지만 명세나 예제와 어긋나 동작을 의심합니다. |

`method`와 `evidence`의 규칙은 다음과 같습니다.

- `integrated`와 `extended` 항목에는 `method`가 필요합니다.
- `method`는 ccxt 표준 camelCase 이름입니다.
- 서비스 객체를 거치는 메서드는 `candles().fetchDailyOHLCV`처럼 `().`로 잇습니다.
- `implicit` 항목의 `method`는 암묵 메서드 이름이거나 `null`입니다.
- `evidence`의 줄 번호는 코드를 넣은 자리 아래로 모두 밀립니다. 자기가 고친 항목만이 아니라 밀린 항목의 줄 번호도 함께 고칩니다.
- `docs:check`는 소스를 읽어 근거를 검사합니다. 줄 번호가 파일 밖이거나, 빈 줄이나 닫는 기호를 가리키거나, 다른 API를 정의하는 줄(상수 값이나 목록 키)을 가리키면 실패합니다.
- KB증권은 API `id`인 TR 코드가 소스에 문자열 값으로 나옵니다. 이런 증권사는 근거 중 적어도 하나가 `id`나 그 `id`를 값으로 가진 상수 이름, `method`를 담아야 합니다.
- `note`에는 줄 번호를 적지 않습니다. 줄 번호는 `evidence`에만 둡니다.

`spec`의 형식은 증권사마다 다릅니다.

- 토스증권은 공식 `openapi.json` 안의 JSON 포인터입니다.
- KB증권은 공식 명세 JSON 파일의 항목 키입니다. 형식은 `#Tkb_<TR 코드>_B2C`입니다.
- 한국투자증권은 공식 예제 저장소의 예제 파일입니다.

### `uniqueFeatures`

ccxt의 통합 메서드로 표현하기 어려운 증권사 고유 기능입니다.

| 키 | 뜻 |
|---|---|
| `name` | 기능 이름입니다. |
| `apis` | 관련 `apis` 항목의 `id` 배열입니다. 없으면 빈 배열입니다. |
| `support` | `지원`, `부분`, `미구현` 중 하나입니다. |
| `scope` | 지원 범위를 적은 설명입니다. |

## `features.json`

기능 하나를 세 증권사에 걸쳐 한 줄로 기록합니다. README의 지원 표가 `features.json`에서 나옵니다.

| 키 | 뜻 |
|---|---|
| `id` | 기능 식별자입니다. ccxt 메서드 이름이 있으면 메서드 이름을 씁니다. |
| `name` | 표에 적는 기능 이름입니다. |
| `group` | 문서에서 표를 나누는 묶음입니다. |
| `hasKeys` | 기능에 대응하는 `has` 키의 배열입니다. 대응하는 키가 없으면 빈 배열입니다. |
| `methods` | 기능을 구현하는 공개 메서드의 기본값입니다. |
| `cells` | `kis`, `toss`, `kbsec`별 셀입니다. |

셀의 키는 다음과 같습니다.

| 키 | 뜻 |
|---|---|
| `status` | 셀 값입니다. 아래 표를 봅니다. |
| `constraint` | 시장이나 조건의 제약입니다. 마침표 없는 문장으로 적습니다. `부분`과 `미검증`에는 필수입니다. |
| `note` | 값을 정하는 데 판단이 들어간 셀의 근거입니다. 문서의 판단 근거 표에 실립니다. |
| `methods` | 증권사가 기능을 구현하는 메서드입니다. 기본값과 다를 때만 적습니다. |
| `apis` | 근거가 되는 `apis` 항목의 `id` 배열입니다. |

셀 값은 여섯 가지입니다.

| 값 | 뜻 |
|---|---|
| `지원` | 증권사가 지원하는 시장에서 모두 구현했습니다. |
| `부분` | 시장이나 조건에 제한이 있습니다. 제약을 `constraint`에 적습니다. |
| `대체` | 증권사 API에 같은 조회가 없어서 다른 조회 결과로 만든 값입니다. ccxt의 `emulated`입니다. |
| `증권사 없음` | 증권사의 공식 API 목록에 같은 기능이 없습니다. |
| `미구현` | 증권사에는 API가 있지만 라이브러리가 아직 구현하지 않았습니다. |
| `미검증` | 구현했지만 실호출로 확인하지 못한 시장이나 조건이 있습니다. |

`부분`과 `미검증` 조건이 함께 있으면 `부분`으로 적습니다.

셀 값은 코드와 다음처럼 맞아야 합니다.

- `hasKeys` 중 하나가 `true`이면 `지원`, `부분`, `미검증` 중 하나입니다.
- `hasKeys`가 `emulated`뿐이면 `대체`입니다.
- `hasKeys`가 모두 `false`이거나 없으면 `미구현`이나 `증권사 없음`입니다.
- `지원`, `부분`, `대체`, `미검증` 셀은 메서드가 클래스에 있어야 합니다.
- `증권사 없음` 셀에는 `apis`를 쓰지 않습니다.

## 언어 중립

자료에는 특정 언어의 표기를 넣지 않습니다.

- 메서드 이름은 ccxt 표준 camelCase가 정본입니다. 언어별 표기는 생성기가 만듭니다.
- `LANGUAGES`에 항목 하나를 더하면 생성기가 언어별 문서를 만듭니다.
- `status`, `method`, `evidence`, `verified`는 지금 저장소의 구현을 기준으로 합니다.
- 다른 언어의 구현이 생기면 네 키를 언어별 객체로 옮기고 `schemaVersion`을 올립니다.
