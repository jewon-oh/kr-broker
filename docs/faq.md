# 자주 묻는 질문

## 앱키는 어디서 발급합니까?

증권사마다 발급 위치가 다릅니다.

| 증권사 | 발급 위치 |
|---|---|
| 한국투자증권 | KIS Developers에서 Open API를 신청합니다. 모의투자 앱키는 따로 받습니다 |
| 토스증권 | 토스증권 WTS 로그인 후 설정 > Open API 메뉴입니다 |
| KB증권 | KB증권 Open API 포털에서 서비스 사용을 신청합니다 |

절차와 `apiKey`, `secret`, `uid` 대응은 [앱키 발급 가이드](guides/credentials.md)에 있습니다.

## 모의 서버가 없는 증권사는 어떻게 시험합니까?

토스증권과 KB증권에는 모의 서버가 없습니다. 두 클래스에서는 `setSandboxMode(true)`가 `NotSupported`를 던집니다.

읽기 요청으로 인증을 확인한 뒤, 체결되지 않을 가격의 1주 지정가 주문을 내고 취소하는 순서로 시험합니다. 절차는 [안전 가이드](SAFETY.md)의 소액 시험 절차에 있습니다.

## OrderOutcomeUnknown이 나오면 어떻게 합니까?

같은 주문을 다시 내지 마십시오. 주문 요청이 시간 초과나 연결 끊김으로 끝나서, 증권사가 주문을 접수했는지 알 수 없다는 뜻입니다.

접수 여부는 `fetchOpenOrders(symbol)`, `fetchMyTrades(symbol)`, `fetchBalance()`, 증권사 앱 순서로 확인합니다.
자세한 절차는 [안전 가이드](SAFETY.md)에 있습니다.

## masterData는 무엇이고 언제 필요합니까?

`options.masterData`는 한국투자증권이 공개하는 종목 마스터 파일의 내용입니다. `KisMasterData` 형식의 객체로 전달합니다.

```ts
const broker = new kis({
    apiKey, secret, uid,
    options: { masterData: { kospi, kosdaq, nasdaq, nyse, amex } },
});
```

각 필드는 종목 배열입니다. 국내 종목은 `code`, `name`, `market`(`KOSPI` 또는 `KOSDAQ`)을 갖습니다. 미국 종목은 `code`, `name`, `market`(거래소 코드), `currency`를 갖습니다.

필요한 경우는 다음과 같습니다.

| 기능 | 증권사 | 마스터 데이터 |
|---|---|---|
| 국내 종목의 시세 조회와 주문 | `kis` | 필요 없습니다. 종목코드 6자리 모양으로 국내를 판별합니다 |
| `fetchMarkets()`와 `loadMarkets()`로 종목 목록 채우기 | `kis` | 필요합니다. 없으면 빈 목록을 반환합니다 |
| 미국 종목의 시세 조회와 주문 | `kis` | 필요합니다. 마스터에 없는 티커는 `BadSymbol`을 던집니다 |
| 미국 종목의 상장 거래소 판별 | `kbsec` | 소스 주석은 필요하다고 적었습니다. 없을 때의 동작은 확인 불가입니다 |

토스증권은 `masterData`를 읽지 않습니다. 종목 목록은 토스증권 API에서 받습니다.

이 저장소는 마스터 파일을 포함하지 않습니다. 소스 주석에 따르면 마스터 파일의 재배포 조건이 명시되어 있지 않기 때문입니다. 마스터 파일을 `KisMasterData`로 바꾸는 변환 도구도 없습니다. 파일 형식과 내려받는 위치는 한국투자증권 공식 자료를 확인하십시오.

## nxtRouting은 무엇입니까?

`options.nxtRouting`은 정규장 밖의 국내 주문을 허용하는 옵션입니다. 넥스트레이드(NXT)의 프리마켓과 애프터마켓이 대상입니다. 기본값은 꺼짐입니다. `true`이거나 `true`를 반환하는 함수를 전달합니다.

증권사마다 동작이 다릅니다.

| 증권사 | `nxtRouting`을 켜면 |
|---|---|
| `kis` | 정규장 밖 국내 주문과 시세를 허용합니다. 주문은 SOR 라우팅으로 나갑니다. 시장가 주문은 지정가로 바꿉니다 |
| `toss` | 정규장 밖 국내 주문을 허용합니다. 지정가 주문만 받습니다 |
| `kbsec` | 정규장 안의 국내 주문을 SOR로 보냅니다. 정규장 밖 주문은 허용하지 않습니다 |

한국투자증권의 소스 주석은 NXT 프리마켓을 08:00부터 08:50까지, 애프터마켓을 15:30부터 20:00까지로 적었습니다.

한국투자증권은 `createOrder`의 `params.session`에 `'nxt'`를 전달하면 주문 한 건만 정규장 밖 주문으로 냅니다.

주문 전에 한국투자증권은 종목의 NXT 거래 가능 여부를 조회하고 6시간 동안 캐시합니다. 거래할 수 없는 종목은 주문을 내지 않습니다. 조회에 실패하면 주문을 그대로 보냅니다.

KB증권은 NXT에 상장되지 않은 종목의 SOR 주문을 증권사가 거절합니다. 이때 라이브러리는 주문을 KRX로 한 번 다시 냅니다. 미상장 종목은 이후 같은 인스턴스에서 주문을 KRX로 바로 냅니다.

미국 주식의 정규장 밖 시장가 주문은 `nxtRouting`이 아니라 `options.usExtendedLimit`이 다룹니다. 토스증권에서만 지원합니다.

## 국내 호가단위는 어떻게 다룹니까?

국내 주식의 호가단위는 가격대마다 다릅니다. ccxt의 `precision.price`는 종목마다 값 하나만 갖기 때문에, `kr-broker` 라이브러리는 국내 종목의 `precision.price`를 비워 둡니다. 미국 종목은 0.01달러입니다.

한국투자증권은 `priceToPrecision()`이 아래 표로 가격을 반올림합니다. 예를 들어 70,123원은 70,100원이 됩니다.

| 가격 | 호가단위 |
|---|---|
| 2,000원 미만 | 1원 |
| 2,000원 이상 5,000원 미만 | 5원 |
| 5,000원 이상 20,000원 미만 | 10원 |
| 20,000원 이상 50,000원 미만 | 50원 |
| 50,000원 이상 200,000원 미만 | 100원 |
| 200,000원 이상 500,000원 미만 | 500원 |
| 500,000원 이상 | 1,000원 |

호가단위 표는 일반 주식용입니다. 종목이 ETF나 ETN이면 표가 달라서 가격을 그대로 전달합니다. 종목 종류는 `masterData`로 압니다. `masterData`가 없으면 모든 국내 종목에 일반 주식 표를 씁니다.

토스증권과 KB증권은 가격을 맞추지 않고 그대로 전달합니다. 호가단위를 어기면 증권사가 주문을 거절하고 라이브러리는 `InvalidOrder`를 던집니다. 토스증권은 `detail`에 `price-tick-invalid`를 담습니다. KB증권은 `detail`에 `PRICE_INVALID`를 담습니다.

호가단위 표가 현재 KRX 규정과 같은지는 확인 불가입니다. 주문 전에 KRX 공지를 확인하십시오.

## 왜 주문을 재시도하지 않습니까?

주문 요청이 시간 초과나 연결 끊김으로 끝나면 증권사가 주문을 접수했는지 알 수 없습니다. 이때 요청을 다시 보내면 같은 주문이 두 번 접수될 수 있습니다.

한국투자증권과 KB증권 클래스에는 멱등키를 보내는 기능이 없습니다. 두 증권사 API가 멱등키를 지원하는지는 확인 불가입니다. 토스증권은 `clientOrderId`를 멱등키로 받지만, 라이브러리는 `clientOrderId`를 자동으로 재사용하지 않습니다.

그래서 주문 요청은 시간 초과나 연결 끊김 뒤에는 `maxRetriesOnFailure`를 설정해도 다시 보내지 않습니다. 시간 초과와 연결 끊김은 `OrderOutcomeUnknown`으로 바뀌어 던져집니다. 이 오류의 `retryable`은 `false`입니다.

조회 요청은 다시 보냅니다. 횟수는 `maxRetriesOnFailure`가 정하고 기본값은 0입니다. 한국투자증권의 기본값은 3입니다.

주문 요청을 다시 보내는 경우가 둘 있습니다. 둘 다 증권사가 응답으로 거절한 요청입니다.

- KB증권과 토스증권은 토큰이 무효라는 응답을 받으면 토큰을 다시 받아 같은 요청을 한 번 더 보냅니다. 주문 요청도 포함합니다.
- KB증권은 NXT 미상장 종목이라는 거절 응답을 받으면 KRX로 한 번 다시 냅니다.
